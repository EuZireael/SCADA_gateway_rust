# PLC-симулятор

Один процесс, который выставляет станцию «родными» способами протоколов и проигрывает по ним 5-суточный архив
настоящих значений станции BN1_MCA1. Нужен, чтобы разрабатывать и проверять шлюз без настоящих контроллеров: на нём идут
все интеграционные тесты, сбои и нагрузка в CI.

**Два режима** (поднимаются только протоколы, теги которых есть в конфигурации):

| Конфигурация | Что отдаёт | Для чего |
|---|---|---|
| `config/station_opcua.yaml` (**по умолчанию**) | **все 2647 каналов базы каналов станции — только по OPC UA** (порты Modbus и PAC закрыты); адрес узла `ns=2;s=<прибор>.<поле>`, как у OPC UA-фасада эмулятора мойки (`ptusa-opcua/`) | стенд `docker compose`, демонстрация, нагрузка; шлюзу нужен тот же `config/stations/BN1_MCA1.yaml`, что и для фасада |
| `config/replay_config.yaml` | 2517 тегов в трёх протоколах (OPC UA 2133, Modbus 212, PAC 173) | интеграционные тесты Modbus и PAC, проверка соответствия прошивке PAC |

Умеет три протокола:

| Протокол | Порт по умолчанию | Что отдаёт |
|---|---|---|
| **OPC UA** (async-opcua) | `4840` | приборы как объекты, поля — типизированные узлы `ns=2;s=<address>` |
| **Modbus TCP** | `5020` | поля как holding-регистры (функции 03, 04, 06, 16) |
| **PAC driver-master** | `10000` | собственный протокол прошивки ptusa: zlib, Lua-снимок приборов, `set_cmd` |

Дополнительно симулятор повторяет **условную логику настоящей прошивки**: часть полей программа ПЛК не отдаёт оператору,
клапаны линий меняются только в ручном режиме, целые поля обрезают дробную часть — см. `docs/FIRMWARE_WRITE_BEHAVIOR.md`.
Эта логика снята с эмулятора мойки (настоящая прошивка ptusa), а не придумана.

## Запуск

```bash
cargo run --release                                     # из папки simulator/: config/station_opcua.yaml, только OPC UA
cargo run --release -- config/replay_config.yaml        # три протокола
docker build -t simulator ./simulator                   # образ (используется в docker-compose.yml)
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPCUA_ENDPOINT` | из конфигурации (`opc.tcp://0.0.0.0:4840`) | адрес привязки и анонса OPC UA; в Docker — резолвимое в сети имя (`opc.tcp://simulator:4840`) |
| `MODBUS_PORT`, `PAC_PORT` | из конфигурации (5020, 10000) | порты Modbus и PAC; если 10000 занят (например, настоящим `ptusa_main`), укажите другой `PAC_PORT` и тот же `SIM_PAC_PORT` шлюзу и тестам |
| `SIM_OPCUA_USER`, `SIM_OPCUA_PASSWORD` | — | включить защищённые конечные точки (Basic256Sha256: Sign и SignAndEncrypt) для пользователя; нужны тестам защищённого OPC UA |
| `RUST_LOG` | `info,opcua=warn` | уровни журнала |

Подкоманды:

| Команда | Что делает |
|---|---|
| `simulator healthcheck [конфигурация]` | проверка живости (порт OPC UA и порты Modbus и PAC, если в конфигурации есть их теги, принимают соединения) — для `HEALTHCHECK` контейнера |
| `simulator station-config [станция] [прежняя] [выход]` | собрать `station_opcua.yaml` из базы каналов станции (`../config/stations/BN1_MCA1.yaml`): тег на каждый канал, все по OPC UA; описание архива и правил прошивки берётся из прежней конфигурации (`config/replay_config.yaml`) по паре прибор + поле. Тест `station::repository_config_covers_the_whole_channel_database_over_opcua` падает, если файл в репозитории устарел |
| `simulator conformance [хост] [порт] [конфигурация]` | проверка **любого** PAC (симулятора или настоящей прошивки): для каждого записываемого PAC-тега записать значение, подождать, перечитать и сравнить с тем, что должна оставить прошивка по правилам из конфигурации. Ненулевой код выхода — расхождение. По умолчанию `127.0.0.1 10000 config/replay_config.yaml` (в `station_opcua.yaml` PAC-тегов нет) |
| `simulator probe-pac [хост] [порт]` | напечатать handshake, объектную модель и снимок любого PAC; по умолчанию `localhost:10000` |

## Как собран `station_opcua.yaml`

Состав каналов определяет **база каналов станции** — `config/stations/BN1_MCA1.yaml` (2647 каналов, 1834 включено в `.cdbx`;
его генерирует `tools/station_config.sh`). Прежний симулятор описывал 2517 тегов, из них только 2028 были каналами базы:
619 каналов (в основном приборы линий и параметры `OBJECT`) в нём отсутствовали, а 489 тегов не имели отношения к базе.
Теперь генератор делает тег на каждый канал: те 2028, что уже были описаны, сохраняют источник значения из архива,
правила записи прошивки, единицу и начальное значение; остальные 619 — статические, с нулевым значением своего типа и
доступом по `writable` канала. Выключенные в базе каналы сервер тоже отдаёт — шлюз их просто не опрашивает.

```bash
cd simulator && cargo build --release
./target/release/simulator station-config      # перегенерировать config/station_opcua.yaml
```

## Конфигурация (`replay_config.yaml`, `station_opcua.yaml`)

```yaml
plc:
  id: BN1-MCA1                       # идентификатор; из него строится URI пространства имён OPC UA
  name: BN1_MCA1 Two-Protocol
  endpoint: opc.tcp://0.0.0.0:4840
  update_rate: 0.5                   # период цикла обновления, секунд
  data_blocks:
    - db_number: 1
      name: BN1_MCA1
      tags:
        - {name: "6", address: "6", type: float, protocol: opcua, device: OBJECT1,
           field: "PAR_MAIN[1].P_CZAD_S", dev_type: Параметры_станции, access: RW, initial: 1.0}
replay:
  enabled: true
  data_path: data/archive_replay.bin.gz
  speed: 1.0                         # во сколько раз быстрее реального времени
  loop: true                         # по окончании архива начать сначала
modbus_port: 5020
pac_port: 10000
```

Поля тега:

| Поле | Назначение |
|---|---|
| `name`, `address` | имя и адрес (адрес по умолчанию — имя). Адрес — `nodeId` в OPC UA и ключ тега в `controllers.yaml` шлюза |
| `type` | `bool`, `int`, `float`, `byte`, `string` |
| `protocol` | `opcua` (по умолчанию), `modbus`, `pac` |
| `device`, `field`, `dev_type` | прибор, поле и тип прибора: OPC UA строит объект `<тип>_<прибор>` с переменной-полем, PAC — приборы и поля снимка |
| `access` | `RW` или `RO`: запись клиента в `RO` отклоняется |
| `initial`, `unit` | начальное значение и единица |
| `modbus_address`, `modbus_type` | адрес регистра и раскладка (`float32`, `int32`, `int16`, `uint16`, `bool`) |
| `replay_source` | ряд архива (по умолчанию — `address`) |
| `replay_mode` | `value` — значение ряда; `integral` — накопленный интеграл (счётчики времени работы); `age` — секунд с последнего изменения |
| `replay_offset`, `replay_valid_min`, `replay_valid_max` | сдвиг во времени; значения вне диапазона считаются обрывом датчика и заменяются последним нормальным |
| `replay_above`, `replay_on`, `replay_off` | порог: выше — `on`, иначе — `off` (дискретный сигнал из аналогового ряда) |
| `replay_scale`, `replay_bias`, `replay_min`, `replay_max` | масштаб, смещение и ограничение результата |
| `write` | `hold` (по умолчанию) — записанное держится; `ignore` — команда принимается (код 0), но значение считает программа ПЛК |
| `write_requires` | запись действует, только если другое поле прибора равно значению: `{field: M, equals: 1}` |
| `write_int`, `write_state` | поле хранится целым (`7.5` → `7`); поле — состояние (целая часть ≠ 0 даёт 1) |

Соответствие конфигурации шлюза: `config/controllers.yaml` и эта конфигурация описывают одни и те же каналы (тот же
`channelId`, типы, адреса и право записи) — это проверяет тест `tests/config_consistency.rs` шлюза.

## Устройство

| Файл | Что делает |
|---|---|
| `main.rs` | запуск: ПЛК, серверы протоколов (только с тегами в конфигурации), цикл обновления, подкоманды |
| `station.rs` | подкоманда `station-config`: конфигурация из базы каналов станции, все теги — OPC UA |
| `config.rs`, `tag.rs`, `value.rs` | конфигурация, тег с правилами прошивки, значения и типы |
| `plc.rs` | общее состояние: значения тегов, запись клиентов, цикл «архив → регистры, узлы, снимок PAC» |
| `replay.rs` | архив `SIMARC01` и вычисление значения канала по модельному времени |
| `opcua.rs`, `modbus.rs`, `pac.rs` | серверы протоколов |
| `pac_client.rs`, `luatab.rs`, `conformance.rs` | клиент PAC, разбор Lua-снимка и проверка соответствия прошивке |

## Тесты

```bash
cargo test            # юнит-тесты: реплей, Modbus, PAC, правила прошивки, конфигурация
cargo fmt --check && cargo clippy --all-targets -- -D warnings
```

Сервер поднимается и в интеграционных тестах шлюза (`cargo test -- --ignored` в корне репозитория).
