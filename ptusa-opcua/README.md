# ptusa-opcua — OPC UA-фасад эмулятора мойки

Отдаёт по OPC UA **все** каналы станции BN1-МСА1 из настоящей прошивки ptusa. Собственный
OPC UA-сервер прошивки (`--opc r|rw`) публикует только `<прибор>.state/.value` — 22 % каналов и
запись, которая на прибор не действует, — поэтому фасад берёт у прошивки весь снимок её родным
протоколом (driver-master) и превращает в узлы OPC UA. Rust (async-opcua + mlua), отдельный пакет
со своим `Cargo.lock`; описание — в документации `src/lib.rs`.

```
прошивка ptusa  ←driver-master→  ptusa-opcua  ←OPC UA :4840→  шлюз
```

- Узел: `ns=2;s=<прибор>.<поле>` (`LINE1V0.ST`, `OBJECT1.RT_PAR_F[12]`, `SYSTEM.UP_TIME`); тип —
  `dataType` канала из конфигурации станции (`config/stations/*.yaml`), запись — `writable`.
- Чтение — снимок раз в `POLL_MS`; исполняется настоящим Lua 5.1 **в песочнице** (снимок присылает
  «прошивка», то есть любой, кто ответит на порту PAC): без `os`/`io`/`load`/байткода, потолок памяти
  64 МБ и 1 с на разбор, распаковка zlib не больше 8 МБ. Нет значения в снимке — `BadNoData`.
- Запись = `__<прибор>:set_cmd('<поле>', <индекс>, v)` ДО сохранения значения; код результата
  прошивки → статус записи (0 — `Good`, иначе `BadInvalidState`). Строка или не число —
  `BadTypeMismatch`.
- Нет связи с прошивкой → все узлы `BadCommunicationError` (сам сервер жив), фасад переподключается
  сам (пауза 1 → 10 с).

Стенд целиком — `docker-compose.moika.yml` в корне репозитория. Запуск без Docker:

```sh
cd ptusa-opcua && cargo build --release
PAC_HOST=127.0.0.1 PAC_PORT=10100 STATION_CONFIG=../config/stations/BN1_MCA1.yaml \
  OPCUA_BIND='[::]:4840' ./target/release/ptusa-opcua
```

`OPCUA_BIND='[::]:4840'` — двойной стек (IPv4 и IPv6): нужен сторонним клиентам OPC UA, которые берут
первый адрес из DNS (`localhost` → `::1`) и не пробуют остальные. Шлюз так не страдает: он сам выбирает
доступный адрес имени, поэтому `PLC_HOST=localhost` работает и с `0.0.0.0:4840`. В контейнере IPv6 может
быть выключен — там `0.0.0.0:4840`, а порт пробрасывает Docker.

Настройки: `PAC_HOST`/`PAC_PORT` (прошивка), `PAC_NAME` (имя прошивки, `PAC_name`: задано — фасад не открывает соединение с прошивкой,
назвавшей себя иначе, значений чужой станции не отдаёт, и команды в неё не идут), `STATION_CONFIG`, `OPCUA_BIND` (на чём слушать),
`OPCUA_ENDPOINT` (адрес в ответе FindServers; конечные точки GetEndpoints строятся из адреса
привязки — async-opcua не разделяет эти два адреса, шлюз подключается по адресу из своего конфига
и анонс не использует), `POLL_MS` (период снимка, 500), `RUST_LOG`. `ptusa-opcua healthcheck` —
проверка для контейнера: порт OPC UA открыт и прошивка отвечает (с `PAC_NAME` — своё имя).

Служебные узлы: `ns=2;s=SYSTEM.PAC_NAME` — имя, которым прошивка назвала себя (по нему шлюз сверяет контроллер: `identity.nodeId`),
`ns=2;s=SYSTEM.LINK_OK` — есть ли связь с прошивкой.

Тесты: `cargo test` — разбор снимка и песочница, конфигурация станции (1834 канала), сценарий
целиком (`tests/facade.rs`: фейковый PAC в проводном формате ptusa + настоящий OPC UA-клиент: чтение,
запись, отказы, обрыв и восстановление связи, ядовитый снимок). Песочница и клиент PAC — копии
`src/sandbox.rs` и `src/pac/` шлюза: при исправлении уязвимости править оба места.
